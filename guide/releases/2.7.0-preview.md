## A lighter Home and programme guide

The programme guide reuses channel labels, logos and measured text as you move through the schedule. Home sizes the YouTube and Prime Video marks for the screen and reuses the active profile and layout while you browse. Programme pictures keep their existing resolution and framing.

Full and Lite now run table and index setup only when a local channel or programme database needs an upgrade. Existing installations upgrade in place. In Full, a channel row and its programme header can share a single logo request and bitmap.

### Measured on Android TV

| Median | 2.6.6-preview | 2.7.0-preview | Change |
| --- | ---: | ---: | ---: |
| Process memory on Home after returning from TV | 34.4 MiB | 28.1 MiB | −18% |
| Process memory in the guide with programme artwork | 40.3 MiB | 31.3 MiB | −22% |
| Enter the guide and draw the listing | 193 ms | 170 ms | −12% |
| Return to Home | 59 ms | 57 ms | 2 ms |
| Java allocations per guide redraw | 22.4 KiB | 6.4 KiB | −71% |
| UI-thread CPU time per guide redraw | 0.707 ms | 0.412 ms | −42% |
| Decoded YouTube and Prime Video marks together | 1.24 MiB | 0.31 MiB | −75% |

The benchmark alternated the two builds on one 3840 × 2160 Android 16 emulator. Each build ran three batches of five warm Home → guide → Home round trips in Full with a named profile, the same six channels, local listings and a programme photograph. The previous build used the published 2.6.6 executable code and assets with its package version code raised solely for in-place benchmark installs. Process memory is proportional set size (PSS), sampled after a collection and settling interval. The CPU and allocation tests ran separately from memory sampling and redrew the actual six-channel guide 60 times per sample onto a software canvas. Playback and physical-TV performance were outside this measurement.
